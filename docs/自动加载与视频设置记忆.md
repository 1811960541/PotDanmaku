## 使用规则

勾选“自动连接唯一的 PotPlayer 窗口”后，程序可以发现已经打开或稍后打开的唯一播放器。存在多个 PotPlayer 时需要选择目标；当前仍只维护一个弹幕会话。点击停止会暂停自动连接，之后可手动连接继续使用。

取得本地视频完整路径后，按以下顺序选择弹幕：

1. 此视频已保存且仍存在的弹幕关联。
2. 同目录、相同文件主名的 `.xml`。
3. 同目录、相同文件主名的 `.json`。
4. 同目录、相同文件主名的 `.ass`。

例如 `第01集.mkv` 可以匹配 `第01集.xml`。已保存的关联文件丢失时回退查找同名文件。匹配按文件主名进行，不猜测集数或模糊匹配名称；格式支持范围仍沿用现有 XML、标准 JSON 和 ASS 子集。

手动选择的弹幕可以与视频不同名、位于其他目录；成功导入后会保存当前视频的关联。如果先手动导入弹幕再连接播放器，首次识别视频时使用这份弹幕并建立关联。

播放器打开其他视频或播放列表进入下一集时，自动读取新路径并重新匹配。切换会隐藏并清除旧弹幕、取消旧导入，较晚完成的旧任务不会覆盖新视频。下一集没有匹配文件时保持连接并提示手动选择，不继续显示上一集弹幕。

## 保存与恢复

视频身份使用不区分大小写的完整路径，因此不同目录中的同名视频不会混用设置。移动或重命名视频后视为新视频，需要重新匹配或关联。

每个视频保存弹幕路径、时间偏移、当前显示设置，以及成功导入时使用的编码、是否包含 ASS 普通字幕和 ASS 样式选择。调整设置后短暂延迟保存；切换、停止和关闭时也会保存。重新打开已关联视频后恢复设置。首次打开的新视频使用启动时的显示设置，时间偏移从零开始。

数据保存为当前配置目录中的 `video-associations.json`：普通模式为 `%LOCALAPPDATA%\PotDanmaku`，便携模式为程序旁的 `data`。使用原子替换并保留上一份 `.backup`；损坏或不支持版本的数据会先备份并提示。如果备份失败，会停用关联写入，避免覆盖原数据。

自动匹配依赖 PotPlayer 返回本地视频路径。网络来源或无法识别的来源仍可手动导入，但不保存为本地视频关联。其他 PotPlayer 版本的接口兼容、多屏和长时间观看仍需继续验收。

## 已完成验证

| 检查 | 结果 | 覆盖内容 |
| --- | --- | --- |
| 核心测试 | 90/90 通过，其中新增 10 项关联测试 | 匹配优先级、关联丢失回退、路径区分、重启读取、备份、无效数据与偏移保护 |
| Windows 会话检查 | 11/11 通过 | 自动 XML 匹配、手动关联、同标题切集、恢复偏移和显示设置、无文件清除、导入竞态、重新打开窗口恢复、手动降级 |
| 真实 PotPlayer 检查 | 2/2 通过 | 自动发现播放器、中文与空格视频路径回传、播放列表自然切集后自动加载下一集 JSON |

核心检查与 Windows 会话检查可在项目目录复跑：

```powershell
dotnet test tests/PotDanmaku.Tests -c Release
dotnet run --project tests/PotDanmaku.SessionTests -c Release
```

真实播放器检查使用合成短视频和播放列表，要求没有其他 PotPlayer 实例正在运行；仅关闭检查自身启动的播放器。按本机安装路径调整参数：

```powershell
dotnet run --project tests/PotDanmaku.SessionTests -c Release -- --real-player 'C:/Path/To/PotPlayerMini64.exe'
```

会话检查在测试输出目录生成 `session-cases/<运行标识>/verification.json`，真实检查另有 `real-player-diagnostics`。本轮验证属于源码功能检查，不代表新版发布包已验证，也不代替完整兼容和用户观看验收。

实现通过 `WM_USER` 的 `0x6020` 查询播放文件名，接收 `WM_COPYDATA` 的 UTF-8 回传，并校验来源和消息大小。接口定义参考 [PotPlayerControl 的命令头文件](https://raw.githubusercontent.com/ld3l/PotPlayerControl/main/InternalSimpleCmd.h)，播放器采样仍在后台使用带超时通信。
