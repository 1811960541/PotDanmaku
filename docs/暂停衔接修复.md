# 暂停衔接修复

日期：2026-11-12。版本：**0.2.0-alpha.1，已打包**。本次修复已包含在新版便携包中；旧 0.1.0-alpha.6 不包含该修复。发布结果见 [本版发布记录](0.2.0-alpha.1发布记录.md)。

用户反馈：播放时按暂停，弹幕会闪一下并退后一段位置。

## 原因与修改

原时钟在播放与暂停切换时，直接使用 PotPlayer 的原始进度重建位置，并清除已经显示的位置。该接口约每半秒更新一次，暂停状态可能先到，最终暂停进度稍后才补报。原始缓存进度通常落后于平滑外推的位置，因此暂停时会回拉；后续补报又会被当作暂停中的跳转，再次改变位置。时间跨过弹幕出现/结束边界时，还会让事件消失或重新出现，看起来像闪动。

新增的带缓存和传递延迟的测试在旧逻辑上复现了 1×约 480 ms、3×约 1,440 ms 的回退；延迟恢复样本还会重复累计传递时间，产生 1×80 ms、3×240 ms 的额外前跳。

本次修改：

- 普通暂停冻结最后显示的位置，保留同一批弹幕及坐标。
- 暂停后的一个有界缓存周期内，允许一次有限幅度的向前进度补报，保持已冻结的画面。窗口按缓存周期和倍速计算，默认约 0.65 秒，最长 1.15 秒；向后变化、大幅前跳、后续调整和窗口过期后的变化仍作为跳转。
- 恢复播放从最后显示时间继续推进，不把较早样本的传递延迟再算一次。
- 跳转检测使用独立的播放器进度预测，按相邻采样间的播放状态和倍速累计；不再把为连续显示保留的位置偏差当成真正跳转。显示时钟仍保留原有渐进纠偏。

播放器适配器继续只读查询。状态切换不要求重建覆盖窗口或绘图设备。

## 接口边界与使用

当前缓存接口没有独立的“用户执行了跳转”标记。暂停后首个缓存周期内，第一次小幅向前跳转可能与最终暂停位置补报无法区分，因而被按补报处理；再次调整、稍后调整及向后或大幅跳转仍生效。此边界尚未作为“暂停后立即逐帧向前完全支持”验收通过，后续需要更精确的进度或跳转信号。

用户随后要求打包，已于 2026-11-12 生成 0.2.0-alpha.1 自包含发布目录和便携 ZIP。实际发布程序集另完成 1×/3×六次暂停恢复检查，共 1,348 帧、788 对相邻暂停帧，回退、暂停跳动、恢复突跳和隐藏采样均为 0；该检查校验了 App/Core/Formats 的实际加载路径、二进制哈希及包内运行时。
