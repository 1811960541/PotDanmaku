# 开发指南

PotDanmaku 使用 .NET 10、WPF 和 Vortice.Windows，在原生透明窗口中通过 D3D11、Direct2D、DirectWrite 和 DirectComposition 绘制弹幕。

## 环境与模块

开发需要 Windows x64、.NET SDK 10.0.401（版本策略见 `global.json`）以及可用的 D3D11 环境。首次 NuGet 还原需要网络。播放器集成验证需要自行安装 PotPlayer。

| 目录 | 职责 |
| --- | --- |
| `src/PotDanmaku.Core` | 媒体时钟、确定性排布、配置模型和视频关联存储 |
| `src/PotDanmaku.Formats` | XML、JSON、ASS 解析和导入报告 |
| `src/PotDanmaku.App` | WPF 界面、播放器通信、原生覆盖窗口和 GPU 渲染 |
| `tests/PotDanmaku.Tests` | 核心、格式和存储测试 |
| `tests/PotDanmaku.SessionTests` | Windows 会话与真实播放器检查驱动 |
| `samples` | 小型合成示例 |
| `packaging/portable` | 便携包说明和默认便携标记 |
| `tools` | 发布、打包、诊断和验证脚本 |

播放器查询每 50 ms 在后台进行，时钟基于单调时间外推。渲染线程持有图形设备，按当前媒体时间查询弹幕，不在跳转后补发整段历史。图形提交统计不等于物理屏幕逐帧测量。

## 构建与测试

```powershell
dotnet build PotDanmaku.sln -c Release
dotnet test PotDanmaku.sln -c Release
dotnet run --project src/PotDanmaku.App -c Release
```

Windows 会话检查单独运行：

```powershell
dotnet run --project tests/PotDanmaku.SessionTests -c Release
dotnet run --project tests/PotDanmaku.SessionTests -c Release -- --real-pause 'C:/Path/To/PotPlayerMini64.exe'
```

真实暂停检查使用单独启动的测试播放器。`--real-player` 切集检查要求没有其他 PotPlayer 实例运行，具体行为见测试源码。

## 发布与验证

```powershell
.\tools\publish.ps1
.\tools\package-portable.ps1
.\tools\verify-portable.ps1 -ZipPath releases/PotDanmaku-0.2.0-alpha.1-portable-win-x64.zip -ReportPath artifacts/portable-verification.json
```

`publish.ps1` 先运行核心测试，再生成 Windows x64 自包含目录和版本 ZIP。`package-portable.ps1` 生成便携目录、ZIP、逐文件清单和压缩包 SHA-256，默认排除个人配置、日志、诊断、PDB 和开发记录；已有同名目录或 ZIP 时拒绝覆盖，可用 `-OutputRoot` 指定新目录。

发布构建规范化源码路径。Git 构建中的提交标识保留在可执行文件产品版本和 `release-info.json` 中，包名使用不含构建元数据的版本号。便携包包含使用指南、合成样本和第三方许可，开发记录保留在源码仓库。

验证实际发布程序集的关联恢复、切集和暂停行为：

```powershell
dotnet publish tests/PotDanmaku.SessionTests -c Release -r win-x64 --self-contained true -o artifacts/PotDanmaku.SessionTests-win-x64
.\tools\verify-release-session.ps1 -PackageDirectory releases/PotDanmaku-0.2.0-alpha.1-portable-win-x64 -ReportPath artifacts/session-verification.json -RealPlayerExecutable 'C:/Path/To/PotPlayerMini64.exe'
```

该检查复制发布文件到项目外的临时目录，核对实际加载的 App/Core/Formats 哈希和包内运行时；不把测试驱动或数据写入冻结发布目录。

## 诊断命令

```powershell
dotnet run --project src/PotDanmaku.App -c Release -- --probe --output artifacts/probe.json
dotnet run --project src/PotDanmaku.App -c Release -- --inspect --file samples/demo.ass --output artifacts/inspect.json
dotnet run --project src/PotDanmaku.App -c Release -- --smoke --portable --file samples/demo.json --seconds 20 --output artifacts/preview-smoke
dotnet run --project src/PotDanmaku.App -c Release -- --playback-smoke --portable --pid 1234 --file samples/demo.ass --seconds 30 --output artifacts/player-smoke
.\tools\analyze-diagnostics.ps1 -Folder artifacts/player-smoke
```

`--inspect` 支持 `--encoding gb18030` 和 `--include-subtitles`，不读取日常显示设置。`--playback-smoke` 的 `--pid` 应替换为测试播放器进程号；省略时连接首个播放器。

冒烟检查退出码 0 表示提交帧数、排布、无图形错误和命中穿透等条件通过；2 表示条件未满足；1 表示导入、连接或其他异常失败。可使用 `--frame-limit 60`/`120` 和 `--simulate-device-loss` 检查限帧与应用内模拟设备恢复。

诊断包含 `summary.json`、`frames.csv`、`player-samples.json` 和 `window-samples.json`。它们记录时钟、坐标、播放器采样、窗口状态和图形健康数据，不保存弹幕正文；可能包含本地路径和标题，发布前需要脱敏。
