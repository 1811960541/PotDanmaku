# 平滑移动修复

日期：2026-10-04。版本：0.1.0-alpha.2。

用户反馈：少量示例弹幕在 PotPlayer 网格测试视频上呈现“一卡一卡”的移动。这不是预期行为，静态截图本身不能判断运动节奏。

## 根因与证据

播放器采样有自己的单调时间戳，经过后台轮询、界面定时器传递后，渲染线程拿到它时已经更晚。alpha.1 的时钟更新把最新渲染位置放回较早的采样时间，再向当前时间外推，重复累计了传递延迟。时钟因此超前，并周期性触发“跳转”重置和回拉。

新增 25 fps 量化、160 Hz 绘制、80 ms 采样延迟的回归测试，在修复前分别复现：0.5×时单帧前进 38 ms，1×前进 79.2 ms，2×前进 158.4 ms，远高于合理的 3.125 / 6.25 / 12.5 ms。

重新检查旧 `artifacts/ass-player/frames.csv`，发现正常播放阶段有约 500 ms 的时钟前跳、约 300 ms 的回拉，并不断增加 discontinuities。旧测试只验提交节奏和暂停冻结，漏掉了带采样延迟的连续播放，这一验收缺口已经纠正。

实际回归还发现，当前播放器的 0x5004 进度查询虽然返回毫秒数，却约每 500 ms 才更新一次。原有 300 ms 不变即判停滞的规则会反复冻结/恢复；重复的缓存读数也不能用于每次重新校准时钟。alpha.2 同时处理了这一问题。此前“25 fps 即 40 ms 时间量化”的模型不适用于这条查询接口。

## 修改

保留采样的原时间戳，用它评估时间误差；改变外推速度时，在最近渲染时间建立连续锚点，既不重复累计延迟，也不把新速度追溯应用到已绘制时段。只有状态切换、真正跳转或停滞转换才重建对应时间段，暂停/seek 原有测试继续通过。

重复进度只更新连接新鲜度，不当作新的位置测量，也不反复减速。按进度变化间隔估计缓存周期，调整跳转阈值；长期不变的停滞判断至少等待 1.5 秒。明确的暂停状态仍立即冻结，大幅 seek 与暂停微小 seek 仍直接应用。缓存接口限制了同步精度，不能承诺仅靠此接口达到每视频帧级的时间测量。

文字绘制同时启用 Direct2D 的 NoSnap 动画选项；官方说明它取消竖直像素对齐，并推荐动画文字使用。此选项不是本次水平周期跳动的根因修复。参考：[Microsoft DrawTextOptions](https://learn.microsoft.com/en-us/windows/win32/api/d2d1/ne-d2d1-d2d1_draw_text_options)。

增加采样延迟、播放状态、倍速、首条弹幕类型与物理坐标诊断，分析连续播放是否有回跳、异常时钟步长或重复移动位置。提交帧率与坐标连续性分别检查。

## 验证

`dotnet test PotDanmaku.sln -c Release`：**53/53 通过**。新增覆盖 0.5/1/2×延迟采样、抖动和乱序传递、延迟倍速转换、500 ms 缓存读数、在缓存周期中途连接。原有暂停/seek、格式与混合轨道测试继续通过。

另从真实播放器记录提取了连续播放区间的 57 条脱敏读数（约 7 秒，已排除后续实际 seek），保存为 `tests/PotDanmaku.Tests/Fixtures/potplayer-cached-progress.json`。在增加 80 ms 传递延迟后以 160 Hz 重放，超过 1,000 个连续帧的时钟步长均在 5.61～6.89 ms 内，无停滞或错误 seek。该测试读取实际时间变化，不依赖提交帧率。

第一轮现场回归暴露了缓存问题；缓存修复后的短冒烟尝试因目标未处于有效前台而记录 0 帧，退出码 2，未纳入性能或视觉结论。图形初始化已在前一轮运行验证，但缓存修复后的最终视觉效果需要重试同片段确认。失败尝试保留于 `artifacts/alpha2-smooth-player/`、`artifacts/alpha2-cached-fixed/`。

发布目录为 `artifacts/PotDanmaku-win-x64`，窗口标题显示版本，以便区分旧程序。

用户随后明确确认“卡顿问题解决了”，本次片段的视觉回归已获得确认。全屏、多屏、全部倍速与长时观看仍需分别验收，不能由这一次反馈或 Present 次数推断所有场景均已通过。
