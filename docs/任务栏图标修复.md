# 任务栏图标尺寸修复

版本：0.1.0-alpha.6，日期：2026-10-04。

用户反馈 alpha.5 的任务栏图标明显偏小，而系统托盘图标正常。

## 原因与修改

alpha.5 使用 `BitmapImage` 读取多尺寸 ICO。本机复现时，WPF 取到的图像只有 16×16 像素；转换为普通图片后也丢失了 ICO 解码器的其他帧。WPF 为大图标生成句柄时，将这张 16×16 图片居中放进较大的透明画布，导致任务栏上的图案缩小。

窗口图标资源改用 `ImageSource` 类型转换器。它创建带有 `IconBitmapDecoder` 的 `BitmapFrame`，保留全部 16、20、24、32、40、48、64、128、256 px 图像。WPF 可针对所需尺寸选择合适的帧。EXE 内嵌 ICO 和系统托盘的读取路径保持不变。

复现和回归使用 `tools/verify-window-icon.ps1`，读取项目的窗口图标资源定义及实际发布程序内嵌的 ICO，通过同一运行时的 WPF 图标转换代码生成句柄，检查透明画布中图案所占的宽高。该检查不替代实际桌面截图或跨屏 DPI 验收。

## 本机回归结果

- alpha.5 的 32×32 图标画布中，图案只有 15×15 像素；修复后为 30×30 像素。
- 16、20、24、32、40、48、64 px 的图标句柄均按请求尺寸生成，图案宽高均占画布的 85% 以上。
- Release 自动测试 80/80 通过；窗口图标仍保留全部 9 个 ICO 尺寸。系统托盘继续使用原有 ICO 和 `System.Drawing.Icon` 读取路径。

## 实现依据

- [Microsoft Window.Icon 文档](https://learn.microsoft.com/en-us/dotnet/api/system.windows.window.icon?view=windowsdesktop-10.0)：窗口图标与程序文件图标独立，并可为不同用途选择 ICO 尺寸。
- [WPF ImageSourceConverter 实现](https://github.com/dotnet/wpf/blob/main/src/Microsoft.DotNet.Wpf/src/PresentationCore/System/Windows/Media/ImageSourceConverter.cs)：URI 转换为 `BitmapFrame`。
- [WPF IconHelper 实现](https://github.com/dotnet/wpf/blob/main/src/Microsoft.DotNet.Wpf/src/PresentationFramework/MS/Internal/AppModel/IconHelper.cs)：多帧 ICO 按尺寸匹配；较小的普通图像居中补透明边距。
